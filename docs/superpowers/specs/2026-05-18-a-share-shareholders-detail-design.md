# A股股票详情股东结构设计

## 背景

在“自选股 -> 股票详情”页中，当前股票详情信息缺少股东结构视角。目标是在股票详情页增加 A 股的“前十大股东”和“前十大流通股东”数据，并展示最新一期相对上一期的变化，同时支持查看最近多期历史。

本设计仅覆盖 A 股股票详情页，不扩展到 ETF、港股、美股或其他市场。

## 目标

- 在股票详情页展示前十大股东列表。
- 在股票详情页展示前十大流通股东列表。
- 默认展示最新报告期，并与上一报告期对比。
- 支持展开查看最近多期历史。
- 支持数据缓存，避免每次进入详情页都打外部数据源。
- 外部数据源失败时不影响股票详情页其他模块。

## 非目标

- 不做股权穿透、最终受益人识别或一致行动人分析。
- 不做股东画像、舆情归因或持仓动机判断。
- 不覆盖 ETF 或非 A 股标的。
- 不在本阶段做批量预加载所有股票股东数据。

## 推荐方案

采用“Tushare 优先 + MongoDB 缓存 + AKShare 兜底”的方案。

Tushare 作为主数据源，分别调用前十大股东和前十大流通股东接口。后端将外部字段归一化后写入 MongoDB。页面读取时默认先查缓存；只有缓存缺失或用户手动刷新时，才尝试外部数据源。Tushare 获取失败时再尝试 AKShare。后端统一计算最新一期与上一期的变化，前端只展示计算结果。

相比前端直接请求数据源，这个方案更容易控制频率、缓存和错误处理，也符合现有 A 股数据接入方式。相比只用 AKShare，这个方案在字段稳定性和后续批量维护上更可控。

## 数据源

### 主数据源

- Tushare 前十大股东接口：`top10_holders`
- Tushare 前十大流通股东接口：`top10_floatholders`

### 兜底数据源

- AKShare 中可用的东方财富股东相关接口。实施阶段必须先检查本地已安装 AKShare 版本暴露的函数，再接入兜底调用；如果本地版本没有可用函数，保留 Tushare + MongoDB 路径并记录清晰日志。

### 缓存

新增 MongoDB 集合 `stock_shareholders`，用于保存归一化后的股东数据。

核心字段：

- `code`：股票代码，使用系统内统一的 6 位 A 股代码。
- `ts_code`：Tushare 代码，例如 `600519.SH`。
- `holder_scope`：`top10` 或 `float_top10`。
- `end_date`：报告期。
- `ann_date`：公告日期。
- `rank`：排名。
- `holder_name`：股东名称。
- `holder_name_normalized`：用于变化计算的归一化名称。
- `hold_amount`：持股数量。
- `hold_ratio`：持股比例。
- `hold_change`：外部源提供的本期持股变化，如有。
- `source`：`tushare` 或 `akshare`。
- `created_at` / `updated_at`：北京时间。

索引：

- `(code, holder_scope, end_date)`
- `(code, holder_scope, holder_name_normalized)`
- `(code, holder_scope, updated_at)`

## 后端接口

新增接口：

`GET /api/stocks/{code}/shareholders`

查询参数：

- `scope`：`top10` 或 `float_top10`，默认 `top10`。
- `periods`：返回最近多少期，默认 `4`。
- `refresh`：是否强制刷新外部数据源，默认 `false`。

返回结构：

```json
{
  "code": "600519",
  "scope": "top10",
  "latest_period": "2025-12-31",
  "previous_period": "2025-09-30",
  "source": "mongodb",
  "last_updated": "2026-05-18T20:00:00+08:00",
  "is_cached": true,
  "latest": [],
  "changes": {
    "new_count": 0,
    "exited_count": 0,
    "increased_count": 0,
    "decreased_count": 0,
    "rank_changed_count": 0,
    "items": []
  },
  "history": []
}
```

变化计算以 `holder_name_normalized` 为匹配键：

- 最新期存在、上一期不存在：`new`
- 上一期存在、最新期不存在：`exited`
- 两期都存在且持股数量或比例增加：`increased`
- 两期都存在且持股数量或比例减少：`decreased`
- 两期都存在且排名变化：记录 `rank_change`
- 两期都存在且无明显变化：`unchanged`

如果缺少上一期，则返回最新列表，变化摘要显示无可对比报告期。

## 前端设计

在 `frontend/src/views/Stocks/Detail.vue` 的股票详情页新增“股东结构”模块。模块位置放在行情/基础指标之后、新闻或分析内容之前。

模块交互：

- 使用页签切换“前十大股东”和“前十大流通股东”。
- 默认选择“前十大股东”。
- 默认展示最新报告期。
- 报告期使用下拉框切换。
- 提供刷新按钮，触发 `refresh=true`。
- 显示数据来源、缓存状态和更新时间。
- 提供“最近多期变化”折叠区域，展开后查看历史报告期列表。

最新期表格字段：

- 排名
- 股东名称
- 持股数量
- 持股比例
- 本期变化
- 排名变化
- 状态

变化摘要字段：

- 新增股东数量
- 退出股东数量
- 增持股东数量
- 减持股东数量
- 排名变化数量

状态展示：

- `新增`
- `退出`
- `增持`
- `减持`
- `持平`
- `无对比期`

## 数据流

1. 用户从自选股进入股票详情页。
2. 股票详情页加载现有行情、基础数据、新闻等模块。
3. 股东结构模块调用 `/api/stocks/{code}/shareholders?scope=top10&periods=4`。
4. 后端优先读取 MongoDB 缓存。
5. 缓存命中时直接返回缓存数据和变化计算结果。
6. 缓存缺失或用户刷新时，后端请求 Tushare。
7. Tushare 失败时尝试 AKShare。
8. 外部数据源成功后写入 MongoDB，并返回统一结构。
9. 外部数据源失败但存在旧缓存时，返回旧缓存并标记缓存状态。
10. 无缓存且外部数据源失败时，股东结构模块展示错误态，股票详情页其他模块继续可用。

## 错误处理

- 无权限或接口不可用：模块内显示“当前数据源暂不可用”，保留刷新入口。
- 无该股票股东数据：展示空状态，不影响其他详情信息。
- 数据源超时：优先展示缓存数据，并在后端记录详细日志。
- 最新期缺少上一期：展示最新列表，变化列显示“无对比期”。
- 股东名称存在轻微差异：后端使用归一化名称计算变化，并保留原始名称展示。
- refresh 请求失败：如果有缓存，返回缓存并附带刷新失败提示；如果没有缓存，返回模块级错误。

外部数据源请求必须复用现有数据源频率控制配置，不新增一套与系统“数据源配置”冲突的限流参数。

## 测试方案

### 后端单元测试

- A 股代码解析为 Tushare `ts_code`。
- Tushare 前十大股东字段归一化。
- Tushare 前十大流通股东字段归一化。
- AKShare 兜底数据字段归一化。
- 最新期与上一期的新增、退出、增持、减持、排名变化计算。
- 缺少上一期时返回“无对比期”。

### API 测试

- 有缓存时不触发外部请求。
- 无缓存时触发 Tushare 并写入 MongoDB。
- Tushare 失败时触发 AKShare。
- 外部请求失败但存在缓存时返回缓存。
- 外部请求失败且无缓存时返回模块级错误。

### 前端测试

- 股票详情页展示“股东结构”模块。
- 可以切换“前十大股东”和“前十大流通股东”。
- 可以切换报告期。
- 刷新按钮调用 `refresh=true`。
- 能展示变化摘要、最新期表格、多期历史和错误态。

### 手工验证

- 使用典型 A 股，例如 `600519` 或 `000001`，验证列表和变化摘要。
- 使用无数据或数据源失败场景，验证详情页其他模块不受影响。
- 验证时间展示使用北京时间。

## 实施边界

本规格只定义功能设计。进入实现前，需要再编写实施计划，明确后端服务、接口、MongoDB 索引、前端组件和验证命令的具体修改顺序。
